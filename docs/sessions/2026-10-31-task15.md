## 1. The cause

The test phone ending in 90 got no answer from Wednesday on although its messages were delivered (✓✓). Its WhatsApp has a
**username**: Meta then sends `messages[].from_user_id` and `contacts[].user_id` / `profile.username`, a business-scoped
user id (BSUID, «EG.…»), and **no `from` / `wa_id`** (seen in n8n's failed run on the server, keys only).
`app.wa_process_event` stored `from` into a NOT NULL column, so the event failed and was lost: 12 messages since
2026-10-28, no alert.

## 4. Differences from the plan

- **Phase A was not released alone:** storing a message without a number needs the same change as Phase B (a key that is
  not a number), so A, B and C go out together.
- **No merge of two clients:** instead a user keeps the key he first had (`wa_contact_keys`), so one person never
  becomes two in the first place.
