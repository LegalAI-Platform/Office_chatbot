## 4. Differences from the prompt, and why

1. **I1 – the upload goes through the panel's nginx** (`/storage/office-sensitive/deliverables/`), not to a
   storage URL in the browser: same origin (no CORS on Garage/R2), the signature is the permission, and nginx
   allows only PUT on that prefix. The API key on `office-sensitive` is now read **and write** (storage-init),
   checked by the healthcheck to write only there (not media, not backups).
2. **I2 – one SQL rule for "what is this file for"** (`file_target`) replaced 0014's `receipt_target`, so the
   booking and the orders cannot disagree (the PR #10 lesson).
3. **I3 – `booking_message_failed` is reused** for a service message that could not be sent (same handling for
   the office: call the client) instead of a new task type.
4. **I4 – the written opinion** is priced at creation (2,000, B-10) and skips `awaiting_price`.
5. **I5 – the e2e receipt is flagged as a duplicate**: the stub has one image, the one L already sent, so
   the order's receipt is `duplicate_suspected` (an alert only, as in TASK 09). The clean path is covered by
   the integration tests.
6. **Fixed during the tests:** the `file_target` query's column names (EF maps them snake_case).
