## 4. Differences from the prompt, and why

1. **The webhook is signed with a header token, not HMAC.** n8n's Webhook node checks a header credential natively
   (`waha-webhook`, like `hazem-internal-send`); checking WAHA's `X-Webhook-Hmac` needs the raw body and a secret inside a
   Code node. The webhook is inside the Docker network only (the edge exposes Meta's webhook alone).
2. **A template is refused on WAHA instead of sent as text.** A template can go out only once Meta approved it, and by
   then the channel goes back to Meta; until then the result is the same as on Meta: the out-of-window reminder becomes
   the office's task. Sending the body as text would need the templates' words in the database.
3. **The session is set by `tools waha-session`** (its webhook with the token, NOWEB's store for the LIDs) rather than
   global environment variables: the token never sits in the compose file, and the store is a per-session option.
4. **The e2e step is 17** (16 is TASK 06's), with its own test number 201000000075.
5. **`import-workflows` now unpublishes** a webhook or schedule whose credentials are missing (before, it was left as it
   was): removing the WAHA keys must stop `WAHA-INBOUND`, and the e2e's temporary credentials must not leave it listening.

## 4b. The independent review (an agent on the code only): nothing in the Meta path; 5 findings in WAHA's, all fixed

| # | Finding | Fix |
|---|---|---|
| 1 | `WAHA-INBOUND` stopped after «Fetch media» when there was no file (n8n gives no item), so a text waited for the minute schedule | «Fetch media» goes on with no data and on its error, as in `META-WA-INBOUND` |
| 2 | «Send to WAHA» was retried after a timeout (copied from a GET node): a client could get a message twice | No retry, as «Send to Meta»; a timeout is a failed send (the API opens its task) |
| 3 | A numbered list stayed active for 24 hours after a text, so a number typed later became an old button | A text or a document sent after it ends the list (`app.waha_sent`); a new `wa-db-tests` check |
| 4 | A WAHA file skipped `whatsapp.media_max_mb` (no size before the download) | `WAHA-MEDIA-ONE` asks WAHA for the size first (HEAD) and `wa_media_precheck` applies the limit as for Meta |
| 5 | e2e step 17: the dry run stayed off after switching back to Meta; «not heard» could pass before n8n had worked; `check-restored` assumed the channel was Meta | Dry run back on with Meta; the check waits past the quiet period; restored = not the stub, no list left |

Kept as known limits (docs/runbooks/waha.md): a file a client sent just before switching back is still fetched from WAHA;
