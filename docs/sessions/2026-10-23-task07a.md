## 0. A bug found before starting: no answer at night (fixed first, with the owner's approval)

The baseline checks were run at 00:00 Cairo time. `backend-test` failed 2 of 266 and `hazem-e2e`
failed 2 of 64: **every turn that opened a staff task between 23:00 and 10:00 answered 500**, so n8n
retried it every minute and the client got no answer until the morning. B-06 due times at night
are Cairo times ("today/tomorrow 10:00", offset +03:00) and Npgsql writes `timestamptz` from UTC
values only. The tests had always run in the day. A staff event with a `+03:00` time failed the
same way.

Fix: every time is converted to UTC in `ConversationStore` before it is written (the instant is
unchanged). New `OfficeHoursApiTests` pin the clock (01:30, 23:30, 09:59 and 12:00 Cairo, and a
staff event at `+03:00`), so the result no longer depends on when the tests run.

## 4. Differences from the prompt, and why

1. **No Identity `UserManager` / EF stores.** ASP.NET Core Identity's `PasswordHasher` (PBKDF2,
   versioned) + cookie authentication + our own lockout on a dbmate table: the EF stores need their
   own schema and package and assume EF migrations (T-21). Same protection, no new package.
2. **The login rate limit is configurable** (`Panel:LoginsPerMinute`, default 10) so the tests,
   which sign in many times a minute, are not blocked; one test checks the 429.
3. **The feature-boundary rule is a test, not an ESLint plugin** (`web/src/architecture.test.ts`):
   no extra dependency. It also checks that only the API client calls `fetch`.
4. **Icons are drawn in the code** (one family of line icons): no icon library was approved.
5. **`node:24.21.0` and `nginx-unprivileged:1.30.4`** pinned (both older than two weeks).
6. **The panel's `web` service starts with `up`** (core), not with a profile: the staff use it daily.
7. **CRLF:** some edited files were saved with LF line endings; Git normalises them (only the real
   line changes show in the diff).
